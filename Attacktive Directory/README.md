# Attacktive Directory — отчёт по машине TryHackMe

> **Сложность:** Medium  
> **Направление:** Active Directory, Kerberos, SMB, атаки на учётные данные  
> **Лаборатория:** [Attacktive Directory на TryHackMe](https://tryhackme.com/room/attacktivedirectory)  
> **Подробное прохождение:** [открыть `WRITEUP.md`](./WRITEUP.md) — содержит спойлеры

## Обзор

Attacktive Directory демонстрирует полный сценарий компрометации домена: обнаружение контроллера, перечисление пользователей, AS-REP Roasting для ошибочно настроенной учётной записи, восстановление пароля, анализ SMB-ресурсов, злоупотребление правами репликации и аутентификация по хэшу администратора.

## Навыки и инструменты

- Перечисление Active Directory и SMB
- Перечисление пользователей Kerberos и AS-REP Roasting
- Офлайн-восстановление паролей
- Анализ общих ресурсов SMB
- Извлечение учётных данных NTDS через DRSUAPI
- Аутентификация Pass-the-Hash
- Nmap, enum4linux-ng, Kerbrute, Impacket, Hashcat, smbclient, Evil-WinRM

## Разведка

Сканирование версий сервисов выявило признаки контроллера домена Windows, включая SMB на TCP-портах 139 и 445. Enum4linux-ng подтвердил среду Active Directory и NetBIOS-имя домена `THM-AD`.

## Перечисление

Kerbrute обнаружил действующие учётные записи в домене `spookysec.local`, включая сервисного пользователя и пользователя резервного копирования. Запрос через Impacket подтвердил, что для одной учётной записи отключена предварительная аутентификация Kerberos. После восстановления её пароля анализ SMB выявил доступный ресурс `backup` с дополнительными доменными реквизитами.

## Эксплуатация

Цепочка атаки объединила несколько недостатков:

1. Для действующей учётной записи была отключена предварительная аутентификация Kerberos.
2. Полученный AS-REP позволял выполнить офлайн-подбор пароля.
3. Найденные реквизиты открывали доступ к SMB-ресурсу резервных копий.
4. В общем ресурсе хранились данные учётной записи с правами репликации каталога.
5. `secretsdump` из состава Impacket получил доменные хэши методом DRSUAPI.

## Повышение привилегий

Хэш администратора позволил пройти Pass-the-Hash-аутентификацию через Evil-WinRM. В результате доступ обычного доменного пользователя был повышен до полного контроля над контроллером домена без знания пароля администратора в открытом виде.

## Влияние

Цепочка привела к полной компрометации Active Directory. Атакующий мог выдавать себя за привилегированных пользователей, получать доступ к доменным данным, выполнять команды на контроллере и закрепляться в инфраструктуре.

## Рекомендации

- Включить предварительную аутентификацию Kerberos для всех учётных записей, кроме документированных исключений.
- Использовать длинные уникальные управляемые пароли для сервисных и резервных учётных записей.
- Удалить лишние права репликации и регулярно проверять субъекты с DCSync-эквивалентными разрешениями.
- Настроить SMB по принципу наименьших привилегий и не хранить реквизиты в общих файлах.
- Включить аудит SMB и оповещения о нетипичном перечислении ресурсов.
- Использовать многоуровневое администрирование и защищённые рабочие станции администраторов.
- Отслеживать AS-REP Roasting, DRSUAPI-запросы не от контроллеров домена и Pass-the-Hash.
